# features/auth/components

## 목적

로그인 전 화면들이 함께 쓰는 틀과 안내 상자를 둡니다. 화면마다 따로 그리면 색·여백·아이콘이 달라지므로 한 곳에 둡니다.

## 주요 파일

| 파일 | 역할 |
|---|---|
| `AuthShell.tsx` | 인증 화면의 공통 셸. 왼쪽 흑연 판(`data-surface="graphite"`, 바탕 `bg-auth-panel`)에는 제품 이름·클립 타임라인 장식 그림(스크린리더에서는 숨김)·한 줄 소개·개인정보 안내 링크·지원 기관 표기를 두고, 오른쪽에는 폼을 둡니다. 폭이 `lg`보다 좁으면 왼쪽 판을 숨기고, 폼 위에 워드마크를, 폼 아래에 안내 링크와 지원 기관 표기를 둡니다. 지원 기관 표기 `SupportNotice`는 최초 설정 화면(`../pages/setup.tsx`)도 가져다 씁니다 |
| `AuthShell.notice.test.ts` | 지원 기관 표기(개발지원 문구와 재단 로고)가 넓은 폭과 좁은 폭의 두 위치에 모두 있는지 소스를 읽어 확인하는 테스트 |
| `kpf-logo.png` | 한국언론진흥재단 로고. 흰 받침 위에 놓습니다 |
| `AuthNotice.tsx` | 안내 상자(`ok`·`note`·`warn`·`bad`). 굵은 결과 한 줄과 작은 안내 한 줄로 나눕니다. 오류는 `role="alert"`, 나머지는 `role="status"`입니다. 폼 아래 링크 모양 `AUTH_LINK`도 여기 둡니다 |

## 설계 이유

- 지원 기관 표기는 지원 사업 협약이 정한 문구라서 화면을 정리하다가 빠지면 안 됩니다. DOM 테스트 도구가 없으므로 테스트가 소스를 읽어 두 위치를 확인합니다.
- 최초 설정 화면은 셸을 따로 그리지만, 초기화하지 않은 배포에서 처음 보이는 화면입니다. 화면마다 표기를 다시 그리면 문구와 로고 받침이 달라지므로 `SupportNotice` 하나를 함께 씁니다.
- 결과와 다음 할 일을 한 문장에 넣으면 좁은 폭에서 줄이 의미와 다르게 끊깁니다. 그래서 안내 상자가 두 줄 구조를 강제합니다.
- 왼쪽 판에는 제품 설명이나 목업을 두지 않습니다. 시선이 오른쪽 폼에 모이게 하기 위해서입니다. 바탕의 호박색 빛과 장식 그림은 왼쪽 판을 평면 흑연색과 구분합니다.
