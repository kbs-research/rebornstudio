# features/auth/pages

## 목적

로그인 전 화면 다섯 개와 동의 화면을 둡니다. 주소 연결은 `../routes.tsx`가 하고, 동의 화면은 보호 셸(`app/_layout.tsx`)이 직접 그립니다.

## 주요 파일

| 파일 | 경로 | 역할 |
|---|---|---|
| `login.tsx` | `/login` | 로그인. 계정이 하나도 없는 배포이면 최초 설정으로 보냅니다. 공개 가입이 없어 계정은 최고관리자가 만든다고 안내합니다. `?next=`는 앱 안 경로일 때만 따릅니다 |
| `password_reset.tsx` | `/password-reset` | 최고관리자가 발급한 링크(`#token=…`, 옛 `?token=…`도 읽음)로 새 비밀번호를 정합니다. 읽은 토큰은 주소창에서 바로 지웁니다. 입력 전에 링크 상태를 확인해 만료 시각을 보여 줍니다. 쓸 수 없는 링크이면 서버가 준 이유(만료·이미 사용·확인 불가)를 제목으로 보입니다 |
| `setup.tsx` | `/setup` | 최초 설정. 셋업 토큰과 첫 최고관리자 정보를 한 폼으로 받습니다. 연동 진단은 인증 없는 화면에 두지 않고 로그인 뒤 플랫폼 개요에서 합니다. 최고관리자를 만들 때도 필수 동의가 필요합니다. 인증 셸을 쓰지 않으므로 지원 기관 표기(`SupportNotice`)를 왼쪽 패널 아래와 좁은 폭의 폼 아래에 따로 둡니다 |
| `setup.notice.test.ts` | | 최초 설정 화면의 지원 기관 표기 두 곳과, 셋업 토큰 명령에 특정 서버 경로·컨테이너 이름이 없는지를 소스를 읽어 확인하는 테스트 |
| `privacy.tsx` | `/privacy` | 개인정보 수집·이용 안내. 수집 항목·이용 목적·보유 기간·동의 거부권과 불이익을 담고, 고지 주체는 설치·운영 기관으로 적고, 바닥에 시행일을 둡니다 |
| `consent.tsx` | (주소 없음) | 동의 화면 `PrivacyConsentPage`. 수집 항목과 보유 기간을 보이고, 필수 동의를 기록합니다. 동의하지 않는 사람에게는 로그아웃과 계정 삭제 요청을 안내합니다 |

## 설계 이유

- 계정이 없는 시스템에 들어가는 방법은 로그인 화면이 안내할 수 없으므로 최초 설정 화면이 맡습니다. 마이그레이션이 계정을 미리 넣지 않는 이유는 저장소에 적힌 비밀번호가 인터넷에 열린 서버에 남기 때문입니다.
- 새 비밀번호를 받기 전에 재설정 링크의 상태를 확인합니다. 만료된 링크로 비밀번호를 두 번 입력한 뒤에야 실패를 알게 되는 일을 막습니다.
- 개인정보 안내는 첫 로그인 전에 읽어야 하므로 로그인 없이 열립니다. 설치마다 시행일이 달라 날짜를 적지 않습니다. 운영 기관이 수집 항목이나 보유 기간을 바꾸면 시행일을 개정일로 적고 개정 이력을 더합니다.
- `?next=`를 그대로 따르면 로그인 화면이 외부 주소로 보내는 통로가 됩니다. 그래서 앱 안 경로만 따릅니다.
