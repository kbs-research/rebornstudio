# features/library/components

## 목적

영상 부품(플레이어·미리보기 창), 콘텐츠 목록의 두 탭, 클립 미리보기, 빈 클립 안내를 둡니다. 영상 부품은 다른 기능도 `../index.ts`에서 가져갑니다.

## 주요 파일

| 파일 | 역할 |
|---|---|
| `VideoPlayer.tsx` | Vidstack 기반 영상 플레이어. 클립 구간 재생, 다운로드 차단, 방향키 ±10초 이동, 재생 주소 갱신(50분마다)을 맡습니다. 재생 주소가 만료되어 미디어 오류가 나면 주소를 한 번 새로 받아 보던 위치부터 이어서 재생합니다. 그래도 실패하면 안내와 다시 시도를 띄웁니다. 머리에 제목이 있는 화면은 `hideTitle`로 컨트롤 줄의 제목을 끕니다 |
| `VideoListPage.tsx` | 콘텐츠 영상 탭. 검색(`q`)·준비 상태 필터(`prep`)는 서버가 적용하고, 조건은 주소에 둡니다. 문제 영상 줄(막힌 위치별 수)을 둡니다 |
| `ClipsPanel.tsx` | 콘텐츠 클립 탭. 썸네일 보기(영상별 묶음)와 표 보기를 전환하고, 검색은 서버가 적용합니다. 검색어와 보기 방식은 주소(`cq`·`view`)에 둡니다. 머리의 수는 서버가 목록과 같은 조건으로 센 값(`clips/count`)입니다 |
| `ClipPreviewModal.tsx` | 클립 탭의 미리보기 창. 왼쪽에서 구간을 재생하고, 오른쪽에 구간·장면 요약·키워드·화자·음성 인식을 보입니다. 채운 버튼은 `클립 보기` 하나입니다 |
| `ClipSummaryText.tsx` | 클립 한 줄 요약의 모양. 음성 인식 문장으로 대신할 때는 앞에 출처 라벨을 붙입니다 |
| `EmptyClips.tsx` | 클립이 0개일 때 없는 이유와 다음 할 일. 준비가 막혔거나 분석 요청 전이면 준비 단계가, 그렇지 않으면 장면 분할(`scene_split`) 단계가 이유를 제공합니다. 관리자에게만 구간 추가 버튼을 둡니다 |

## 설계 이유

- 재생 위치는 원본 `<video>`의 절대 시간으로 읽고, 이동은 Vidstack의 클립 상대 API로 합니다. `VideoPlayer` 모듈 주석과 `hooks/useClipPlayhead.ts`가 이 규칙을 함께 지킵니다.
- 클립 탭의 검색어 파라미터 이름에는 `c`를 붙입니다(`cq`). 같은 주소에 영상 탭의 `q`가 함께 있어서, 탭을 오가도 두 탭의 검색어가 각각 남습니다.
- 썸네일 보기에서 한 영상의 클립이 두 페이지에 걸치면 묶음 머리가 한 번 더 나옵니다. 불러온 순서를 바꿔 합치면 `더 보기`를 누른 뒤 새 카드가 위쪽에 끼어들기 때문입니다.
- 빈 클립의 이유는 준비 타임라인에서 받습니다. 분석 스택(분석 서비스·샷 검출)을 여기서 다시 추측하면 두 곳의 판단이 달라집니다.
- 서버(`create_manual`)는 관리자에게만 구간 추가를 허용합니다. 그래서 관리자에게만 버튼을 보입니다. 버튼을 모두에게 보이면 라벨러·검수자가 눌러 이유를 알 수 없는 실패를 봅니다.
