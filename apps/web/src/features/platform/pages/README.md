# features/platform/pages

## 목적

최고관리자의 플랫폼 화면 네 개를 둡니다. `../routes.tsx`가 이 화면들을 플랫폼 가드(`platform`) 아래에 연결합니다.

## 주요 파일

| 파일 | 경로 | 역할 |
|---|---|---|
| `admin_global.tsx` | `/admin` | 플랫폼 개요. 조치 필요 카드 하나(막힌 연동, 할 일이 없으면 한 줄로 접힘)만 둡니다. 연동 상태는 15분 주기 점검 결과와 마지막 자동 점검 시각을 보이고, 클라이언트 주소·TLS는 서버가 개요 요청으로 다시 판정합니다. 프로젝트의 진척은 프로젝트 개요에서, 분석 비용은 프로젝트의 영상 등록 단계에서 봅니다 |
| `admin_users.tsx` | `/admin/users` | 사용자 관리. 공개 가입이 없어 계정은 여기서 만듭니다. `계정 만들기`가 이메일·이름·플랫폼 역할을 받고 1회용 비밀번호 설정 링크를 보여 줍니다. 표 하나에서 플랫폼 역할 변경·정지와 해제·비밀번호 재설정 링크 발급·활동 이력을 다룹니다. 활동 이력의 프로젝트 이름은 프로젝트 목록(`GET /projects`, 최고관리자는 모든 프로젝트)으로 붙입니다 |
| `connections.tsx` | `/admin/connections` | 자격증명 연결. 서비스 묶음별(캡션 품질검수 모델·저장소와 분석 서비스) 연결 카드를 보입니다. 연결 추가·수정·삭제를 둡니다. 저장하면 서버가 같은 요청에서 점검하고, 점검이 정상이 아니면 저장은 남긴 채 경고 토스트와 행의 사유·고치는 방법으로 알립니다. 따로 누르는 점검 버튼은 없습니다. Bedrock 모델은 ID를 직접 입력합니다. 추가 창은 처음 등록하는 NCP Object Storage를 기본으로 고르고, 서비스 목록은 저장소·분석 묶음을 캡션 품질검수 모델 묶음보다 앞에 둡니다. 사용처가 있는 연결은 지울 수 없고, 먼저 할 일을 안내합니다. 목록을 받은 뒤 사용처가 생겨 삭제가 거절되면(409 `connection_in_use`) 삭제 창을 닫지 않고 거절 응답의 프로젝트 이름으로 사용 중 안내를 보입니다. 편집 창은 엔드포인트·리전·API 주소를 바꾸면 키 칸을 필수로 바꾸고 키를 넣기 전에는 저장을 막습니다(`lib/connection_address`). Bedrock 연결은 두 키 칸이 늘 필수이고, 저장된 키가 없거나 한쪽만 입력하면 저장을 막고 키 칸 아래에 이유를 보입니다. 서버도 같은 판정으로 422 `bedrock_keys_required`를 돌려줍니다. NCP 저장소 연결에는 허용 저장소 목록 입력란이 있고, 프로젝트가 쓰는 저장소를 빼려다 거절되면(409 `allowed_bucket_in_use`) 사용 중인 프로젝트 이름과 먼저 할 일을 창 안에 표시합니다 |

## 설계 이유

- 시크릿은 쓰기 전용입니다. 서버는 시크릿을 돌려주지 않으므로 화면에서는 값을 넣을 수만 있고 다시 볼 수 없습니다. 편집할 때 시크릿을 비우면 기존 값을 그대로 둡니다.
  저장하면 서버가 자격증명을 실제로 호출해 봅니다. 저장만 하고 써 보지 않으면 등록은 됐는데 분석만 안 되는 실패를 알아채지 못합니다. 점검이 정상인 새 연결은 프로젝트 설정에서 바로 고를 수 있습니다.
