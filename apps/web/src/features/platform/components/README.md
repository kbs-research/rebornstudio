# features/platform/components

## 목적

플랫폼 화면과 다른 기능이 함께 그리는 연동 진단 부품을 둡니다. 다른 폴더에서는 `../index.ts`로 가져옵니다.

## 주요 파일

| 파일 | 역할 |
|---|---|
| `DiagnosticsList.tsx` | 연동 진단 결과 목록 `DiagnosticsList`(판정·이름·측정값과 안내, 실패·주의를 먼저 표시)와 요약 문구 `diagnosticsSummary`(`8건 중 5건 정상 · 실패 1 · 주의 2` 형식). 목록은 프로젝트 설정(저장소·분석 연결 카드)이 쓰고, 요약은 그 화면들과 플랫폼 개요가 씁니다 |
| `DiagnosticsList.test.ts` | 요약이 점검 기록이 없는 항목(`unchecked`)을 주의로 세지 않는지 확인하는 테스트 |

## 설계 이유

- 같은 진단 응답을 화면마다 각자 그리면 판정 색과 문구가 달라집니다. 그래서 그리는 부품을 하나로 두고, 타입도 계약 타입을 그대로 씁니다.
- 요약은 분모부터 씁니다. 전체 건수와 정상 수를 먼저 쓰고, 정상이 아닌 항목을 종류별로 붙입니다. 주의가 남아 있는데 이상 없음이라고 쓰지 않도록 주의를 따로 셉니다.
  확인 전 항목은 이상이 아니므로 주의로 세지 않고 색도 주지 않습니다.
- 부품은 그리기만 합니다. 진단은 저장소·분석 서비스·워커를 실제로 호출하므로 자동으로 실행되면 안 됩니다. 플랫폼 개요는 서버의 주기 점검 결과를 읽고, 프로젝트 설정은 대상 점검 버튼으로 부릅니다.
