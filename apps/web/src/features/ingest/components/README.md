# features/ingest/components

## 목적

영상 등록 단계의 본문, 등록 시트와 엔진, 등록 Job 목록, 준비 과정을 그리는 부품을 둡니다. 준비 타임라인은 영상 상세(`features/library`)도 `../index.ts`에서 가져갑니다.

## 주요 파일

등록 단계 본문과 등록:

| 파일 | 역할 |
|---|---|
| `IngestPage.tsx` | 영상 등록 단계 본문. 상태 타일·등록 묶음 표·Job 상세를 둡니다. 영상 목록을 상태별로 모아 보는 보기는 없고, 분석 요청과 문제 조치는 Job 상세에서 합니다. 문제 조치는 행마다 `문제 해결` 메뉴로 한 건씩 합니다. 확인 창을 거치는 조치(분석 요청·분석 재요청·요약 재요청)도 모두 여기 있습니다. 이전 주소의 `?tab=storage`로 들어오면 등록 창을 엽니다 |
| `IngestSheet.tsx` | 등록 시트. 출처 탭(NCP 먼저), 공통 설정(Job 제목·변환 방식), 확인 줄(대상·알려진 길이, 분모 표시), 전체 진행 한 줄로 이루어집니다. 열릴 때 업로드 조건(`upload-limits`)을 한 번 조회해 엔진에 넘깁니다. 업로드 중에 닫으면 숨기기만 하므로 엔진이 계속 돕니다. 숨긴 동안에는 `role="dialog"`를 뗍니다. 열린 동안에는 `useDialogFocus`로 포커스를 시트 안에 가둡니다 |
| `UploadQueue.tsx` | 로컬 파일 업로드 엔진. 드롭존, 큐, 영상 생성, 멀티파트 시작, 파트 서명·업로드(동시 3건), 확정 순서로 진행합니다. 받기 전에 확장자·크기 상한으로 거르고, 거른 파일은 따로 줄에 남깁니다. 행마다 중단·실패 사유·다음 행동(재시도 또는 제거)을 두고, 확정 응답의 중복(`duplicate_of`)을 행에 표시합니다. 제목 입력란은 비워 두고, 비운 채 올리면 파일 이름으로 등록합니다 |
| `StoragePathInput.tsx` | 버킷 경로 직접 입력. 파일 경로 여러 줄을 등록하고(서버가 요청당 200건까지 받으므로 나눠 보냄), 폴더 경로를 넣으면 폴더 단위 등록(서버 비동기 작업)을 맡깁니다. 버킷 안을 나열하는 화면은 없습니다. 저장소에 없는 경로는 서버가 거절하고 그 경로를 입력란 아래에 보입니다 |
| `IngestJobsPanel.tsx` | 등록 Job 목록(커서 페이지, `DataTable`). 출처·상태 필터를 주소(`source`·`state`)에 두고, 남은 영상이 없는 묶음은 접힌 목록에 둡니다 |
| `IngestStatusTiles.tsx` | 상태 타일 세 개(요청 대기·분석 중·문제). 수와 합계(총 길이·예상 비용·가장 오래된 요청의 경과 시간)는 서버 집계(`videos/buckets`)를 씁니다. 누르는 동작은 없습니다 |

| `JobRail.tsx` | Job 상세 오른쪽의 분석 요청 카드. 요청 대기 수와 금액 확정 시점 안내를 둡니다 |
| `JobIssueBanner.tsx` | Job 상세 맨 위의 실패 요약 띠 |

| `PrepTimeline.test.ts` | 장면 요약 실패 줄의 렌더 테스트. 서버 `retryable`에 따라 재요청 버튼을 두거나 빼고, `retryLabels`로 버튼 이름이 `요약 재요청`이 되는지 서버 렌더러(`react-dom/server`)로 그려 확인합니다 |

## 설계 이유

- 범용 `DataTable`을 쓰지 않고 `MediaRow` 행으로 그립니다. 등록 화면의 행은 정렬해 비교하는 데이터가 아니라 지금 처리할 작업입니다. grid 한 줄로 열을 맞추고 조치를 슬롯으로 두면 썸네일 열·조치 폭 상수·정렬 끄기 설정이 필요 없습니다.
- 이슈 조치는 막힌 위치마다 하나이고 영상 한 건씩 합니다. 검증은 검증 재검사, 분석본 변환은 변환 재시도, 분석은 분석 재요청(과금이 생기므로 확인 창을 거침), 장면 요약을 받지 못한 영상은 요약 재요청(장면 요약만 다시 요청하고 확인 창을 거침)입니다. 행 메뉴와 영상 상세의 준비 진행이 같은 이름과 대상을 씁니다. 여러 건을 한 번에 다시 시도하는 버튼은 두지 않습니다. 분석 요청 정보가 빠진 영상은 사유만 보이고 조치가 없습니다.
- 저장소 탭은 버킷을 탐색하지 않고 경로를 받습니다. 허용 버킷·연결·앱 경로·저장소 존재 확인은 서버가 등록 전에 하고, 영상 규격은 등록 뒤 규격 검증이 확인합니다.
- 등록 시트는 분석 요청을 묻지 않습니다. 분석은 과금되는 결정이라 대상과 예상 비용을 분석 요청 확인 창에서 보고 정합니다. 클립 길이는 모든 프로젝트가 같은 기본값을 쓰므로 요청마다 고르지 않습니다.
- 중복 업로드는 막지 않고 알립니다(`duplicate_of`). 같은 파일인지는 서버가 내용 해시로 판정합니다.
- 대부분의 부품은 직접 조회하지 않고 props로 값을 받습니다.
- 색은 `../lib/vocab.ts`의 색조 표를 거쳐 토큰 유틸로만 씁니다.
