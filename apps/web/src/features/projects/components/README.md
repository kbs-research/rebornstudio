# features/projects/components

## 목적

프로젝트 하나의 성격과 상태를 보여 주는 부품을 둡니다. 진척률·연결 안내·프로젝트 없음 상태는 다른 기능도 `../index.ts`에서 가져가 씁니다.

## 주요 파일

| 파일 | 역할 |
|---|---|
| `ProjectShellState.tsx` | 주소의 프로젝트를 찾지 못했을 때의 상태. 조회 실패(다시 시도)와 프로젝트 없음을 구분합니다. `dense`는 패널 한 칸용입니다. 멤버·콘텐츠·영상 상세·통계 화면이 씁니다 |
| `ConnectionNotice.tsx` | 쓸 수 있는 저장소·분석 연결이 없거나 프로젝트가 대상을 저장하지 않았을 때의 안내(결과 한 줄, 해결 방법 한 줄, 설정 링크). 서버가 준 `storage_ready`·`analysis_ready`·`*_stack_missing`을 읽기만 합니다. 등록 화면·개요·설정이 씁니다 |
| `ConnectionNotice.test.ts` | 저장소가 없으면 등록이 막혔다고, 분석이 없으면 분석 요청만 막혔다고 쓰는지 확인하는 테스트 |
| `NoConnectionNotice.tsx` | 고를 연결이 하나도 없을 때의 안내. 최고관리자에게는 자격증명 연결 화면 링크를, 그 밖의 사람에게는 누가 연결을 등록하는지를 씁니다. 대상 카드와 생성 화면이 씁니다 |
| `NoConnectionNotice.test.ts` | 무엇이 없는지와 어디서 등록하는지를 두 줄로 나누는지 확인하는 테스트 |
| `StorageTargetCard.tsx` | 설정 분석 연동의 저장소 대상 카드. 등록한 NCP 저장소 연결과 버킷을 고르고 점검·저장합니다. 버킷 목록은 서버가 연결의 허용 범위 안 것만 주고, 목록을 읽지 못하면 연결의 허용 범위(`allowed_buckets`)에서 고릅니다. 고를 저장소가 없으면 최고관리자에게 넓혀 달라는 안내를 같은 카드에 둡니다. 연결을 고르기 전에는 이름을 직접 적습니다. 첫 영상이 등록되면 선택을 끄고, 고정된 이유를 같은 카드에 씁니다 |
| `AnalysisTargetCard.tsx` | 설정 분석 연동의 분석 대상 카드. 분석 연결·워크스페이스·분석 프로젝트를 고르고 점검·저장합니다. 선택지를 읽다가 일시 오류가 나면 주의 톤으로 보이고, 15초 간격으로 네 번까지 다시 조회합니다. 첫 영상이 등록되면 선택을 끕니다. 고른 워크스페이스의 연동 저장소가 프로젝트 저장소와 다르면 저장을 막습니다 |
| `TargetNotice.tsx` | 두 대상 카드 안의 두 줄 안내(굵은 결과와 작은 이유) |
| `AnalysisStackCard.tsx` | 이 프로젝트가 어떤 분석 스택(저장소·캡션 초안·영상 나누기)으로 만들어졌는지 보입니다. 만든 뒤에는 바꿀 수 없다는 표시를 카드 머리에 둡니다 |

## 설계 이유

- 개요와 통계가 같은 진척 응답을 읽습니다. 화면마다 그릴 내용을 따로 정하면 같은 상태를 다른 말로 부르고, 한 화면에만 줄이 생깁니다. 그래서 부품 하나가 그리고, 통계에만 쓰는 막대는 `children`으로 넣습니다.
- 프로젝트 조회가 실패했는데 없음이라고 쓰면 서버 장애를 프로젝트 부재로 읽게 됩니다. 그래서 `ProjectShellState`가 두 경우를 구분합니다.
- 저장소·분석 대상의 규칙·잠금·점검은 서버(`services/stacks/project_storage`·`project_stack`)가 정하고, 카드는 그 결과를 그립니다. 미리 채워 두는 기본 연결은 없습니다.
- 첫 영상이 등록되면 그 영상의 에셋이 이미 고른 대상에 저장되어 있습니다. 대상이 둘로 나뉘면 폴링·정리·재분석이 어느 쪽을 봐야 할지 알 수 없습니다. 그래서 선택을 잠그고 이유를 같은 카드에 씁니다.
- 벤더 분석기가 없는 스택에는 캡션 초안이 없다고 씁니다. 영상을 나누는 어댑터 이름을 초안 칸에 적으면 샷 검출이 초안을 만드는 것처럼 읽힙니다.
