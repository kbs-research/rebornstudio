# features/pipeline/components

## 목적

작업 단계 화면의 단계 패널과 그 부품을 둡니다. 대기열 카드의 낱말, 머리 오른쪽 영역, 완료 클립 본문은 다른 기능도 `../index.ts`에서 가져갑니다.

## 주요 파일

| 파일 | 역할 |
|---|---|
| `HeaderActions.tsx` | 작업 단계 화면 머리 오른쪽 영역(갱신 시각·주 버튼). 활성 패널이 내용을 채웁니다. 머리가 없는 화면에서는 부품이 놓인 위치에 그립니다. 영상 등록 단계도 씁니다 |
| `NextWorkCard.tsx` | 두 대기열(라벨링·검수)이 함께 쓰는 다음 작업 카드. 머리(대기 수·보유 수), 보유 작업 미리보기나 빈 상태, 주 버튼 하나(`다음 작업`·`다음 검수`), 실패 배너를 그립니다. 큐별 낱말 `QUEUE_SPEC`, 대기 수 문구 `queueCountLabels`, 실패 문구 `nextErrorText`, 대기 수 실패 판정 `poolFailed`도 여기 있습니다. `내 작업`도 `../index.ts`로 가져갑니다 |
| `queue_scope.test.ts` | 다음 작업 카드의 대기 수와 버튼 낱말 테스트 |
| `WorkPanel.tsx` | 라벨링 단계. 화면을 연 사람의 다음 작업 카드입니다. 보유한 작업이 있으면 그 클립과 재작업 횟수를 미리 보여 줍니다 |
| `ReviewInboxPanel.tsx` | 검수 단계. 화면을 연 사람의 다음 검수 카드입니다. 보유한 검수가 있으면 그 클립과 익명 라벨러를 미리 보여 줍니다 |
| `DonePanel.tsx` | 완료 단계. 승인되어 내보내기에 실릴 클립을 보입니다. 서버가 내보내기와 같은 쿼리(`approved_rows_stmt`)로 준 행을 거르지 않고 그립니다. 필터 축도 서버가 적용합니다(`?filter=`) |
| `ExportPanel.tsx` | 내보내기. 지금 내보내면 실리는 클립 수, 납품 불가·규칙만 검사 링크, 내보내기 추가 창(전체·검수용 샘플, 선택 항목 제외), 이력과 다운로드를 둡니다. 다운로드 링크는 누를 때 받습니다(presigned URL은 만료되기 때문). 품질검수를 기다리느라 시작을 미룬 행은 지연으로 세지 않고, 늦어도 시작하는 시각을 씁니다 |
| `DeidentReportsCard.tsx` | 라벨링 단계 아래의 비식별화 신고 카드. 라벨러나 검수자가 비식별화 미흡을 신고해 작업이 멈춘 클립을 신고 사유·위치·신고자·장면 프레임과 함께 보이고, 행마다 `재개`와 `제외`를 둡니다. 제외는 이 화면에서 되돌릴 수 없어 사유를 받는 확인 창을 거칩니다. 머리의 수는 서버가 센 `total`이고, 실린 행이 그보다 적으면 `전체 N건 중 M건`으로 밝힙니다. 대상이 없으면 그리지 않습니다. 장면 프레임을 불러오지 못하면(만료되거나 CSP 저장소 출처 밖인 분석 서비스 썸네일) 영상 아이콘을 둡니다 |
| `RepeatedRejectsCard.tsx` | 라벨링 단계 아래의 반려 누적 카드. 반려가 기준 횟수 이상 쌓인 미완 작업을 보유자·마지막 반려 사유와 함께 보입니다. 기준 횟수는 서버 응답을 쓰고, 대상이 없으면 그리지 않습니다 |
| `CompletedClipView.tsx` | 완료 클립의 읽기 전용 본문. 완료 상세와 완료 워크벤치(`features/workbench`)가 함께 씁니다. 품질검수 보류 건(404 `qc_held`)에는 보류 사유와 보류 목록 링크를 보입니다 |
| `ClipRangeCell.tsx` | 내 작업 표의 클립 구간 칸. `ClipRangeCell`은 `clip_id`로 클립을 조회해 칩을 그리고, `ClipRangeChip`은 구간을 이미 알 때 칩만 그립니다 |

## 설계 이유

- 두 큐의 문구를 `NextWorkCard` 한 곳에 둡니다. 같은 일을 하는 화면이 위치마다 다른 말을 쓰면, 역할이 바뀐 작업자가 매번 다시 배워야 합니다. 큐를 더할 때는 `QueueKind`에 한 줄을 더하고 단위를 정합니다.
- 머리의 수는 `99+`로 줄이지 않습니다. `99+`는 좁은 배지에만 씁니다. 단위는 작업은 `건`, 영상·클립은 `개`입니다.
- 주 버튼은 역할마다 하나입니다(`다음 작업`·`다음 검수`). 한 사람은 역할마다 한 건씩 맡고, 서버가 보유한 작업을 먼저 다시 줍니다. 고를 수 있는 목록, 반납, 남은 시간은 없습니다.
- 다음 작업 뮤테이션과 조회는 `features/me`의 훅(`useLabelQueue`·`useReviewQueue`)이 맡습니다. `내 작업`과 작업 단계 화면이 같은 키를 무효화하고 같은 워크벤치를 엽니다.
- 완료 목록에서 고른 축 때문에 모든 행이 같은 값이 되는 칸은 뺍니다. 납품 불가 축에서만 그 칸을 사유 칸으로 바꿉니다. 사용자가 그 축을 고르는 이유가 사유를 보려는 것이기 때문입니다.
- 비식별화 신고 카드의 판정은 관리자가 합니다. 카드는 신고 내용과 장면 프레임을 판단 근거로 같은 행에 두고, 처리 뒤에는 신고 목록·단계 요약·작업 키를 함께 무효화합니다.
- 반려 누적 카드는 흐름을 바꾸는 버튼을 두지 않습니다. 반려된 작업은 만든 사람이 재작업하고, 관리자는 같은 사유가 되풀이되는지 보고 가이드나 클립을 고칩니다.
- 경계를 편집할 때 확인할 것은 앞 클립이 어디서 끝나는지입니다. 그래서 이웃 클립을 함께 그립니다.
