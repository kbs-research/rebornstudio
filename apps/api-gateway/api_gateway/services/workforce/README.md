# services/workforce

작업자 운영 도메인입니다. 작업 자체(가져오기·제출·검수)는 `work`가 맡고, 이 패키지는 사람 쪽 기록을 본인에게 보여 주는 조회를 맡습니다. 본인 판정 목록과 본인 로그인 이력이 여기에 속합니다.
이 패키지는 사람을 평가하지 않습니다. 도구는 기록을 보여 주고, 판단은 사람이 합니다.

## 주요 파일

| 파일 | 역할 |
|---|---|
| `decisions.py` | 호출한 사용자가 내린 검수 판정(`reviews`)을 최신순 커서 페이지로 돌려줍니다. 전체 수를 함께 주고, 지표는 만들지 않습니다 |
| `login_history.py` | 호출한 사용자의 로그인·로그아웃·로그인 실패·로그인 잠금 이력을 최신순으로 돌려줍니다 |

## 설계 이유

- 두 조회 모두 경로에 사용자 ID를 받지 않고 늘 호출한 사용자의 기록을 돌려줍니다. 로그인 이력은 플랫폼 전체에서 쌓이고 IP와 브라우저를 담으므로 다른 사람의 이력을 읽는 경로를 두지 않습니다.
- 로그인 이력은 허용 목록(`_AUTH_EVENT_TYPES`)의 이벤트만 싣습니다. 세션 갱신(`auth.refreshed`)이 섞이면 상한 안의 행이 거의 모두 세션 갱신이 됩니다.
- 로그인 이벤트 기록 자체는 인증 서비스(`auth.service`)가 남깁니다. 이 패키지는 읽기만 합니다.
- `work_items`·`reviews`는 읽기만 합니다. 쓰기는 `work`가 맡습니다.

## 의존성

- 부르는 것: `models`(DomainEvent·WorkItem·Review·Clip·Video·User), `services.authz`·`reject_reasons`
- 부르는 쪽: `api/v1/workforce.py`(본인 판정 목록·본인 로그인 이력). 주기 작업은 없습니다.
- `api/v1/workforce.py`의 작업 이력·프로젝트 나가기 경로는 이 패키지가 아니라 `work`·`org` 서비스를 부릅니다. 이 라우터는 작업자 화면을 기준으로 경로를 묶었습니다.
